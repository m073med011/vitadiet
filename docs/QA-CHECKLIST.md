# قائمة فحص QA النهائي - المرحلة 3

الفحوص الآلية جزء من البناء، أما ما تبقى فيحتاج تنفيذاً يدوياً على نسخة مرفوعة فعلاً.
هذه القائمة هي ما يجب المرور عليه قبل اعتماد المرحلة.

## 1. الفحوص الآلية (تعمل داخل `npm run generate`)

```bash
npm run format:check
npm run lint
npm run typecheck
npm run generate
```

| الفحص           | ما يغطيه من متطلبات المرحلة                       |
| --------------- | ------------------------------------------------- |
| `test:catalog`  | سلامة بيانات المنتجات وAlt Text وروابط الشراء     |
| `test:content`  | محاور الجودة، الصفحات القانونية، وحدة بريد B2B    |
| `test:contrast` | WCAG AA Contrast على مستوى التوكنات               |
| `test:urls`     | عدم تسرب `localhost` إلى المنشور                  |
| `test:schema`   | Canonical WebSite/Organization/Product/Breadcrumb |
| `test:i18n`     | تطابق مفاتيح اللغتين، لا مفاتيح ميتة              |
| `test:site-url` | تطابق النطاق بين الكود و`.htaccess`               |
| `test:delivery` | Indexability وأبعاد الصور المولّدة                |
| `failOnError`   | لا صفحة مولّدة بخطأ 4xx/5xx أثناء الـPrerender    |

## 2. الفحص اليدوي المطلوب

### 2.1 الأجهزة

- [ ] Desktop عرض 1440 و1280.
- [ ] Tablet عرض 1024 و768.
- [ ] Mobile عرض 390 و360 (الحد الأدنى المستهدف).
- [ ] لا يوجد Scroll أفقي في أي عرض.
- [ ] العربية RTL والإنجليزية LTR: الاتجاه، المحاذاة، الأيقونات المنعكسة.

### 2.2 لوحة المفاتيح

- [ ] رابط «تخطي إلى المحتوى الرئيسي» أول عنصر في ترتيب Tab ويعمل.
- [ ] كل رابط وزر وحقل قابل للوصول بـTab وله Focus مرئي واضح.
- [ ] القائمة الجانبية في الجوال: Escape يغلق، Tab يبقى داخلها، والتركيز يعود لزر الفتح.
- [ ] نافذة أماكن الشراء: Escape يغلق، Tab يبقى داخلها، والتركيز يعود للزر الذي فتحها.
- [ ] الأسئلة الشائعة تفتح وتغلق بـEnter وSpace.
- [ ] ملخص أخطاء نموذج الشراكة يستقبل التركيز، وروابطه تنقل التركيز إلى الحقل نفسه.

### 2.3 قارئ الشاشة

- [ ] عناوين الصفحات: `h1` واحد لكل صفحة وتسلسل عناوين منطقي.
- [ ] كل حقل في النموذج مرتبط بـ`label` صحيح، ورسالة الخطأ مقروءة عبر `aria-describedby`.
- [ ] قائمة المنتجات الأفقية لا تكرر المحتوى، وشريط الصور المتحرك في الجوال مخفي عن
      قارئ الشاشة (`aria-hidden`).
- [ ] حالة الإرسال تُعلن عبر منطقة `aria-live`.

### 2.4 الحركة والعرض

- [ ] تفعيل `prefers-reduced-motion` في النظام: تتوقف حركة الشريط المتحرك وتأثيرات
      الظهور والدوائر المتحركة.
- [ ] تكبير الصفحة إلى 200% دون فقدان محتوى أو تداخل.

### 2.5 النماذج

- [ ] إرسال فارغ: تظهر رسائل التحقق ولا يُرسل شيء.
- [ ] بريد غير صحيح ورقم هاتف غير صحيح: رسالة مناسبة لكل منهما.
- [ ] بدون الموافقة على الخصوصية: لا يُرسل الطلب.
- [ ] إرسال صحيح: تصل الرسالة إلى `acc@vitadiet.sa` وتظهر لوحة النجاح.
- [ ] الضغط المزدوج على زر الإرسال يُنتج طلباً واحداً فقط.
- [ ] قطع الاتصال ثم الإرسال: تظهر حالة Network Error.
- [ ] تعطيل نقطة النهاية مؤقتاً: تظهر حالة Server Error.
- [ ] تعطيل JavaScript: تظهر كتلة `noscript` ببريد التواصل، وبقية الصفحات تُقرأ طبيعياً.

### 2.6 الروابط

- [ ] كل روابط منصات البيع تفتح صفحة المنتج الصحيحة في المنصة.
- [ ] الروابط الخارجية تحمل `rel="noopener noreferrer"` وتفتح في تبويب جديد.
- [ ] روابط LinkedIn وSnapchat وInstagram تفتح الوجهة النهائية مباشرة بدون تحويل وسيط.
- [ ] لا يوجد رابط داخلي يمر بتحويل: كل الروابط الداخلية بشرطة مائلة في نهايتها.

### 2.7 المتصفح

- [ ] Console خالٍ من الأخطاء الحرجة على كل نوع صفحة.
- [ ] لا توجد تحذيرات Hydration في وضع الإنتاج.
- [ ] الصور تُحمَّل بالمقاسات المولّدة ولا يوجد 404 في تبويب Network.

## 3. Screaming Frog

بعد الرفع النهائي على الإنتاج:

1. زحف كامل لـ`https://www.vitadiet.sa/`.
2. تأكيد صفر روابط داخلية بحالة 3xx أو 4xx أو 5xx.
3. تأكيد `Canonical` ذاتي الإشارة لكل صفحة.
4. تأكيد `hreflang` متبادل بين العربية والإنجليزية على كل صفحة.
5. تأكيد عدم وجود `noindex` على أي صفحة إنتاج.
6. تأكيد وجود عنوان ووصف فريدين لكل صفحة.
7. تأكيد ظهور Product وOffer وBreadcrumb وFAQ في تبويب Structured Data.
8. مقارنة عدد الصفحات المزحوفة بعدد الروابط في `sitemap_index.xml`.
