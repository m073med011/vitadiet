# نموذج الشراكة - التشغيل والربط

الصفحة: `/partners/` (وبالإنجليزية `/en/partners/`).

النموذج **لا يعتمد على `mailto`**. زر «ابدأ شراكتك» يفتح صفحة النموذج، والنموذج يرسل
الطلب فعلياً عبر HTTP. عنوان البريد يبقى معروضاً في الصفحة كخيار إضافي لمن يفضّله.

---

## 1. المسار الكامل للطلب

```
app/components/partner/Form.vue        الواجهة، الحالات، منع الإرسال المزدوج
        ↓
app/services/partner-lead.ts           التحقق + طبقة الإرسال (fetch واحد)
        ↓
runtimeConfig.public.partnerFormEndpoint
        ↓
public/api/partner-lead.php            المعالج الافتراضي: تحقق ثانٍ + إرسال بريد
        ↓
acc@vitadiet.sa                        البريد الموحد المعتمد
```

---

## 2. البريد المعتمد

البريد الموحد للاستقبال هو:

```
acc@vitadiet.sa
```

وهو معرّف في مكان واحد: `CONTACT.email` داخل `shared/brand.ts`، ويُستخدم في الفوتر،
وصفحة الشراكة، ورسائل الخطأ، و`Organization.email` في Schema.org.

`npm run test:content` يقارن هذه القيمة بمستقبِل الرسائل في `public/api/partner-lead.php`
ويفشل البناء عند اختلافهما، وكذلك يفشل إذا ظهر بريد `@vitadiet.sa` آخر داخل ملف المحتوى.
هذا هو الضمان التقني لشرط «بريد B2B موحد».

> بريد `b2b@vitadiet.sa` **لم يعد مستخدماً** في الموقع بعد اعتماد `acc@vitadiet.sa`.
> أي تغيير للبريد لاحقاً يتم في `shared/brand.ts` و`public/api/partner-lead.php` معاً،
> وإلا يفشل البناء.

## 3. تغيير وجهة الإرسال (CRM لاحقاً)

الوجهة قيمة إعداد وليست رابطاً مكتوباً داخل المكوّن:

```ts
// nuxt.config.ts
runtimeConfig: {
  public: {
    partnerFormEndpoint: '/api/partner-lead.php',
  },
}
```

للتحويل إلى CRM أو Webhook لاحقاً، اضبط متغير البيئة قبل البناء:

```bash
NUXT_PUBLIC_PARTNER_FORM_ENDPOINT="https://crm.example.com/hooks/vitadiet" npm run generate
```

```powershell
$env:NUXT_PUBLIC_PARTNER_FORM_ENDPOINT = "https://crm.example.com/hooks/vitadiet"
npm run generate
```

الشرط الوحيد على الوجهة الجديدة أن تُعيد:

- `200` مع جسم JSON فيه `{"ok": true}` عند النجاح.
- أي حالة أخرى، أو جسم ليس JSON، تُعامل كخطأ خادم.

وإذا كانت الوجهة على نطاق مختلف، يجب أن تسمح بـCORS من `https://www.vitadiet.sa`.

## 4. المعالج الافتراضي (PHP)

`public/api/partner-lead.php` يُرفع مع الموقع إلى Apache ويعمل على استضافة cPanel
الاعتيادية. وظيفته:

- يقبل `POST` فقط بجسم JSON لا يتجاوز 20KB.
- يعيد التحقق من كل الحقول على الخادم (تحقق المتصفح راحة للمستخدم وليس ضماناً).
- ينظّف أي `CR`/`LF` من الحقول التي تدخل ترويسات البريد، لمنع Header Injection.
- يرسل من `no-reply@www.vitadiet.sa` ويضع بريد المرسل في `Reply-To`، حتى تبقى سياسات
  SPF/DKIM سليمة ويظل الرد على الطلب ممكناً بضغطة واحدة.

**يحتاج تأكيداً من الإدارة/الاستضافة:** أن دالة `mail()` مفعّلة على الخادم. إذا كانت
معطّلة سيعيد المعالج `502` وسيظهر للزائر «تعذر إرسال الطلب» مع بريد التواصل المباشر.
البديل الموصى به عندها هو SMTP مصادق عليه أو خدمة إرسال، أو نقل الوجهة إلى CRM كما في
القسم 3.

`public/.htaccess` يضيف على هذا الملف `X-Robots-Tag: noindex, nofollow` و`Cache-Control: no-store`.

## 5. الحالات المنفَّذة

| الحالة           | ما يراه الزائر                                                                 |
| ---------------- | ------------------------------------------------------------------------------ |
| Default          | النموذج فارغ، بدون أي رسالة خطأ.                                               |
| Validation       | ملخص أخطاء في أعلى النموذج ينتقل إليه التركيز، ورسالة نصية بأيقونة تحت كل حقل. |
| Loading          | زر الإرسال معطّل مع `aria-busy` ومؤشر دوران ونص «جار الإرسال...».              |
| Success          | لوحة نجاح تستقبل التركيز، مع خيار إرسال طلب آخر.                               |
| Server Error     | رسالة خطأ خادم مع بريد التواصل المباشر.                                        |
| Network Error    | رسالة انقطاع اتصال مع اقتراح إعادة المحاولة وبريد التواصل.                     |
| JavaScript معطّل | كتلة `<noscript>` توضّح أن الإرسال يحتاج JavaScript وتعطي البريد المباشر.      |

**منع الإرسال المزدوج** مطبَّق بطبقتين: تعطيل الزر أثناء الطلب، وحارس داخل معالج
`submit` يتجاهل أي إرسال جديد ما دام الطلب السابق مفتوحاً (يغطي ضغط Enter المتكرر).

## 6. الخصوصية

- الحقول المرسلة محددة في `PartnerLead` داخل `app/types/index.ts` فقط.
- الموافقة على سياسة الخصوصية حقل إلزامي، ولا يُرسل الطلب بدونها.
- `hint` تحت حقل الرسالة ينبّه صراحة إلى عدم إرسال أي معلومات صحية شخصية.
- ما يُجمع ولماذا وكم يُحفظ موصوف في `/legal/privacy-policy/`، ومصدر نصها
  `app/data/site-content.ts`.
